# Шаг 4. Применение Chain-of-Thought техники

## Выбранная задача

**Добавить в калькулятор историю вычислений.**
Пользователь выполняет расчёты — они сохраняются в список. Список отображается на странице. Можно очистить историю.

## Почему эта задача сложная

Она затрагивает сразу несколько частей приложения: интерфейс (новый блок на странице), логику (сохранение операций), структуру данных (массив с записями). Одним промптом её решать рискованно — легко получить запутанный код. Поэтому применяем **Chain-of-Thought**: разбиваем задачу на шаги и решаем последовательно.

## Декомпозиция задачи

Задача разбита на **4 логических шага**:

1. Спроектировать структуру данных и логику хранения истории
2. Добавить HTML-разметку и CSS для блока истории
3. Написать JS-логику сохранения операций и отображения
4. Подключить сохранение истории к существующим вычислениям

## Шаг 1. Проектирование структуры данных

**Промпт:**
> **Role:** Ты Senior Frontend Developer.
> **Task:** Предложи структуру данных и логику для хранения истории вычислений в калькуляторе на чистом JS.
> **Context:** Проект — калькулятор на HTML5 + CSS3 + JavaScript, всё в одном index.html. Без библиотек. История должна храниться в памяти (не localStorage).
> **Format:** Краткое описание (5–7 строк): какие переменные завести, какого типа, что в них хранится.

**Результат:** Получена структура — массив `history` из объектов вида `{ expression, result }`, где `expression` — строка «5 + 3», `result` — число 8.

## Шаг 2. HTML и CSS для блока истории

**Промпт:**
> **Role:** Ты Senior Frontend Developer.
> **Task:** Добавь в index.html блок для отображения истории вычислений и кнопку «Очистить историю».
> **Context:** Калькулятор на чистом JS. Блок должен быть под основным полем. Стиль — минималистичный, тёмная тема, как в основном калькуляторе.
> **Format:** Готовый HTML-код блока + CSS-стили для него.

**Результат:** В разметку добавлен `<div class="history">` со списком `<ul>` и кнопкой «Очистить историю». Стили подобраны в тон основному дизайну.

## Шаг 3. JS-логика сохранения и отображения

**Промпт:**
> **Role:** Ты Senior Frontend Developer.
> **Task:** Напиши функции: `addToHistory(expression, result)`, `renderHistory()`, `clearHistory()`. Первая добавляет запись в массив, вторая перерисовывает список в DOM, третья очищает массив и DOM.
> **Context:** Калькулятор на чистом JS, всё в index.html. Стиль: camelCase, const/let, комментарии на русском. Без eval().
> **Format:** Готовый JS-код трёх функций с комментариями.

**Результат:** Получены три рабочие функции. `addToHistory` добавляет в массив, `renderHistory` строит список через `createElement` и `textContent`, `clearHistory` очищает массив и список.

## Шаг 4. Подключение к существующим вычислениям

**Промпт:**
> **Role:** Ты Senior Frontend Developer.
> **Task:** Найди в существующем коде место, где происходит вычисление результата при нажатии «=», и добавь вызов `addToHistory()` с правильными аргументами.
> **Context:** Вот текущий код обработчика «=»: (вставить фрагмент). Нужно, чтобы после каждого успешного вычисления запись попадала в историю.
> **Format:** Покажи только изменённый фрагмент кода и объясни в 1–2 строках, что изменилось.

**Результат:** В обработчик кнопки «=» добавлен вызов `addToHistory(expression, result)` и последующий `renderHistory()`. История обновляется при каждом вычислении.

## Итог по Chain-of-Thought

Разбив задачу на 4 шага, удалось:
- Избежать путаницы в одном большом промпте
- На каждом шаге фокусироваться на одной части (данные → UI → логика → интеграция)
- Легко откатить или переделать отдельный шаг, если что-то не понравилось

Техника Chain-of-Thought здесь сработала эффективнее, чем попытка решить задачу одним запросом.

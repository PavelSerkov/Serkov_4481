# Отчёт о разработке: Фитнес-клуб «ИМПУЛЬС»

## 1. Общая информация

**Проект:** Адаптивное frontend-приложение для фитнес-клуба «ИМПУЛЬС».

**Цель:** разработать веб-приложение для просмотра расписания тренировок и записи на групповые занятия с использованием AI-агента.

**Технологический стек:** React 18, Vite, Tailwind CSS, Vitest, React Testing Library, JavaScript.

**AI-агент:** Codex (OpenAI).

**Источники данных для разработки:**
- `project_description.md` — описание проекта из ДЗ 3
- `user_stories.md` — пользовательские истории из ДЗ 3
- `technical_specification.md` — ТЗ из ДЗ 3
- `2_rules.md` — файл системных правил из ДЗ 2
- `reference.png` — выбранная UI-концепция из ДЗ 3

## 2. Процесс разработки

Разработка велась **пошагово** с AI-агентом Codex. Перед началом агенту был передан подробный промпт с описанием стека, функций MVP и пошагового плана работ. Агент работал строго по шагам с остановками для проверки после каждого этапа.

### Шаг 1. Инициализация проекта

**Промпт (фрагмент):**
> Создай структуру проекта React + Vite + Tailwind с конфигурационными файлами (package.json, vite.config.js, tailwind.config.js, postcss.config.js), точкой входа index.html и базовой заглушкой App.jsx.

**Результат:** создана структура проекта из 9 файлов. Проект успешно запущен командой `npm run dev`, страница отвечает HTTP 200 по адресу `http://localhost:5173/`.

### Шаг 2. Mock-данные

**Промпт (фрагмент):**
> Создай `src/data/trainings.js` — массив из 6–8 объектов с полями id, title, date, time, type, trainer, place, slots. Типы: Йога, Силовая, Кардио. У одной тренировки slots: 0.

**Результат:** создано 8 тренировок на период 12–18 октября 2026 года, все три типа представлены, одна тренировка (`id 4`, «Йога для спины») имеет `slots: 0`.

### Шаг 3. Реализация компонентов

**Промпт (фрагмент):**
> Реализуй 5 компонентов (Header, FilterBar, TrainingCard, TrainingList, ConfirmModal) и обнови App.jsx согласно reference.png. Стиль: оранжево-красный градиент, тёмный фон, скруглённые углы. Предусмотри состояния loading/error/empty/success.

**Результат:**
- Созданы 5 компонентов + обновлён App.jsx
- Работает фильтрация (Йога — 3, Силовая — 3, Кардио — 2, Все — 8)
- Работает модальное окно подтверждения
- Работает toast на 3 секунды после записи
- Тренировка без мест имеет неактивную кнопку

**Проблема:** React выдал предупреждение о том, что у кнопок фильтра не указан `key`.
**Решение:** агент самостоятельно обнаружил проблему в консоли браузера и исправил, добавив атрибут `key`.

### Шаг 4. Адаптивная вёрстка

**Промпт (фрагмент):**
> Проверь адаптивность на 375px, 768px, 1024px+. Используй классы Tailwind sm:, md:, lg:. Исправь проблемы, если найдутся.

**Результат:** адаптивность работает изначально — правок не потребовалось.
- 375px — 1 колонка, фильтры горизонтально скроллятся
- 768px — 2 колонки
- 1024px+ — 3 колонки
- Модальное окно на мобильном корректно помещается в viewport

### Шаг 5. Тестирование

**Промпт (фрагмент):**
> Создай минимум 3 автотеста (Vitest + React Testing Library): фильтрация по типу, вызов onBook при клике, disabled-состояние при slots: 0.

**Результат:** создано 2 файла тестов:
- `TrainingList.test.jsx` — проверка фильтрации
- `TrainingCard.test.jsx` — проверка вызова onBook и disabled-состояния

**Итог:** 3 теста, все проходят (`Test Files 2 passed, Tests 3 passed, Exit code 0`).

### Шаг 6. README.md

**Промпт (фрагмент):**
> Создай README.md с разделами: название и описание, стек, установка и запуск, структура, реализованные функции, скриншот.

**Результат:** README.md создан со всеми требуемыми разделами.

## 3. Применённые техники работы с AI

### Пошаговая разработка с остановками

Вместо одного большого промпта использовалась стратегия **декомпозиции задачи на 6 шагов**. После каждого шага агент останавливался для проверки. Это позволило:
- Контролировать качество на каждом этапе
- Вовремя исправлять ошибки
- Избежать накопления проблем

### Файл системных правил

Перед началом работы агенту был передан файл `.clinerules` (аналог из ДЗ 2) — `2_rules.md`. Агент работал с учётом правил: camelCase для JS, комментарии на русском, `const`/`let`, без `console.log` в финальном коде.

### Отладка через анализ вывода браузера

Агент самостоятельно запускал браузер и проверял консоль. Обнаружив React-предупреждение о `key`, он исправил его без дополнительных промптов.

### Итеративные уточнения

При возникновении проблем (зависание `npm install`, ограничения песочницы) агент корректировал команды и повторял действия, объясняя причины.

## 5. Проблемы и решения

| Проблема | Решение |
|---|---|
| `npm install` зависал из-за ограничений песочницы | Повторный запуск вне файлового ограничения |
| Vite не мог прочитать `vite.config.js` в песочнице | Запуск команды вне ограничения, успешно |
| React-предупреждение о `key` у кнопок фильтра | Агент обнаружил в консоли и исправил самостоятельно |
| Обнаружены 13 уязвимостей npm | `audit fix --force` не запускался (может сломать зависимости), уязвимости не критичны для учебного проекта |

## 6. Выводы и рекомендации

### Что сработало хорошо

- **Пошаговая декомпозиция** — самый эффективный приём. Задачи в 6 шагов решались быстрее, чем одна большая.
- **Чёткий промпт с контекстом** — агент сразу понял стек, функции и стиль.
- **Проверка после каждого шага** — позволила ловить баги до накопления.
- **Файл правил** — агент соблюдал стиль и добавлял комментарии к сложной логике.

### Что можно улучшить

- Песочница Codex ограничивает чтение файлов выше рабочей папки — из-за этого часть команд приходилось запускать вручную в терминале.
- Для сложных проектов стоит сразу прописывать все ограничения в промпте, чтобы избежать уточнений.

### Рекомендации

- **Для похожих проектов:** использовать ту же схему — ТЗ → правила → пошаговая разработка → проверка.
- **Для продакшена:** добавить TypeScript, ESLint, Prettier, CI/CD.
- **Для расширения функционала:** добавить личный кабинет, отмену записей, уведомления.
